# تمرین عملی HTTP

## ۱. اجرای سرویس فقط در شبکهٔ داخلی

سرویس باید روی یک آدرس خصوصی یا روی `127.0.0.1` (وقتی پراکسی در همان میزبان است) گوش کند. پورت آن نباید روی رابط عمومی منتشر شود و فایروال نیز باید دسترسی به آن را به پراکسی و کاربران مجاز محدود کند. تنها پراکسی در ورودی شبکه پورت عمومی دارد. در این پروژه `httpbin` فقط به شبکهٔ داخلی Docker متصل است و هیچ `ports`ای برای آن تعریف نشده؛ پراکسی به هر دو شبکهٔ عمومی و داخلی وصل است و درخواست‌های ورودی پورت ۸۰ را به `httpbin:8081` می‌فرستد. این جداسازی جایگزین کنترل دسترسی روی خود پراکسی نیست.

## ۲. فلسفهٔ TLS Termination

در TLS termination، ارتباط TLS کاربر در پراکسی پایان می‌یابد: پراکسی گواهی را ارائه می‌کند، ترافیک را رمزگشایی می‌کند و سپس درخواست را به سرویس قدیمی می‌فرستد. بنابراین بدون تغییر دادن سرویس قدیمی می‌توان محرمانگی و صحت ترافیک مسیر اینترنت را فراهم کرد و مدیریت گواهی‌ها را در یک نقطه انجام داد. اگر مسیر پراکسی تا سرویس داخلی هم قابل اعتماد نباشد، آن مسیر نیز باید با TLS محافظت شود. TLS به‌تنهایی هویت یا مجوز کاربر را تعیین نمی‌کند؛ برای آن در این پروژه JWT بررسی می‌شود.

این نمونه مطابق صورت تمرین روی پورت ۸۰ کار می‌کند. چون HTTP ساده توکن Bearer را در مسیر شبکه آشکار می‌کند، برای استفادهٔ واقعی باید TLS روی پراکسی یا در ورودی جلوی آن فعال شود، پورت ۴۴۳ برای HTTPS باز باشد و پورت ۸۰ به HTTPS هدایت شود. تا آن زمان، این پیکربندی فقط برای اجرای آزمایشی در محیط کنترل‌شده مناسب است.

## ۳. پراکسی احراز هویت JWT

پراکسی فقط توکن‌های `HS256` با امضای معتبر، `iss` و `aud` درست، `sub` غیرخالی، زمان انقضای آینده و `nbf` غیرآینده را می‌پذیرد. درخواست نامعتبر با `401` رد می‌شود و اصلاً به `httpbin` نمی‌رسد. هدرهای `Authorization` و `Proxy-Authorization` پیش از ارسال به سرویس داخلی حذف می‌شوند. توکن نمونه با دستور `mint` تولید می‌شود و یک ساعت اعتبار دارد. کلید امضا باید محرمانه و حداقل ۳۲ بایت باشد؛ `.env` در Git نادیده گرفته می‌شود.

پیش‌نیاز: Docker با Compose و یک پورت ۸۰ آزاد. فایل `.env` را با یک کلید تصادفی بسازید:

```sh
printf 'JWT_SECRET=%s\n' "$(openssl rand -hex 32)" > .env
docker compose up --build -d
```

یک توکن بسازید و رفتار پراکسی را بررسی کنید:

```sh
docker compose run --rm --no-deps proxy mint alice
curl -i http://localhost/get
curl -i -H 'Authorization: Bearer <TOKEN>' http://localhost/get
```

در دستور آخر، `<TOKEN>` را با خروجی دستور اول جایگزین کنید. درخواست بدون توکن `401` و درخواست دارای توکن معتبر پاسخ `httpbin` را برمی‌گرداند. برای اجرای آزمون کد: `go test ./...`.

تصویر استفاده‌شده: [go-httpbin](https://github.com/mccutchen/go-httpbin)، با `PORT=8081` مطابق [راهنمای رسمی پیکربندی](https://github.com/mccutchen/go-httpbin#configuration).
